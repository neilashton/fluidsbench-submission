# Surface-only aerodynamic submissions

AhmedML, WindsorML and HiLiftAeroML accept `prediction_scope: surface_only` in the candidate path. Complete surface pressure and wall shear, force evaluation and every required Cp cut remain mandatory over the exact test case set. Volume prediction files, volume output mappings and velocity-profile predictions are omitted. Raw metrics for those unavailable predictions must also be omitted.

The existing weights are retained. Volume velocity (15%), volume pressure (10%) and velocity profiles (15%) contribute zero, without renormalization. A perfect surface-only result scores 60/100; full surface-and-volume results retain their 100/100 ceiling. Field and diagnostic group ceilings are 50/100 and 40/100 respectively; force scores can still reach 100/100.

For AhmedML, pass `--prediction-scope surface_only` to the case evaluator and dataset scorer and omit `--volume-prediction-manifest`. Set `prediction_scope` in the package config and set the inference attestation scope to `all_declared_cases_and_surface_fields`. Supply only checkpoints required by the surface model and declare only surface predicted fields in the methodology. Discretization records must map every required surface, scalar-force and Cp support, with complete coverage. The assembler re-reduces the complete evidence before writing a package.

For WindsorML, pass `prediction_scope="surface_only"` to the native case evaluator and dataset scorer. Omit `volume_manifest`, retain the evaluator-owned profile support, and retain both constant and relative Cp families. Neither velocity family is included. WindsorML still uses its existing candidate APIs and package format; this change does not introduce a new participant assembler.

For HiLiftAeroML, set `prediction_scope` in the package config and supply the surface native output root. The aggregate artifact manifest, each case record and each native receipt must also declare the same scope. Case input digests omit `volume_support` and `volume_regional`; receipt domains contain only `surface`. Every surface summary, load, native field support and Cp artifact remains checksum-bound. The compact participant NPZ contains only `cp_q_delta`, and profile index/chunk metadata declares the scope and omits `volume_velocity`. The independent reader checks exact scope, case coverage, support metadata and canonical artifact bytes before recomputing Cp scores. The frozen original HiLift methodology contract is preserved; surface-only entries use `methodology-prediction-scopes-v1.json`.

The additive evaluator is bound by `reference/aerodynamic-surface-only-implementation-v1.json`. New surface-only submission and evaluation evidence files carry `prediction_scope_implementation_binding`; historical full-domain evaluator release bindings remain intact. Run `python scripts/refresh_surface_only_implementation.py --check` to verify the new binding. Intentional implementation changes require regeneration with the same script and review of the resulting hashes.

Candidate status, owner review, published support and submission-opening gates continue to apply. This extension does not activate a dataset or approve any result.
